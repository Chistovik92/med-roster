Все заметные изменения в этом проекте документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),

## [0.10.0] - 2026-11-27

### Новое — интеграционный слой API (для МИС и внешних систем)
- **Версионированный контракт `/api/v1`:** все эндпоинты доступны с префиксом
  `/api/v1` (контракт для МИС). OpenAPI-схема — `GET /api/openapi.json`
  (описывает только `/api/v1`), Swagger UI — `GET /api/docs`, ReDoc —
  `GET /api/redoc`. Прежние пути `/api/...` сохранены без изменений
  (обратная совместимость, в схему не входят).
- **API-ключи (`X-API-Key`):** один ключ = один тенант (клиника/МИС). Формат
  `mrk_` + 40 hex; в БД хранится только SHA-256 хэш, полный ключ показывается
  ровно один раз при выпуске. Пока ключей не выпущено, сервер работает в
  прежнем «открытом» режиме; как только выпущен хоть один ключ — внешние
  анонимные запросы закрываются (401). Локальный UI (с того же компьютера)
  работает без ключа всегда.
- **Управление ключами** (только локально или по `X-Admin-Token`):
  `GET/POST /api/keys`, `DELETE /api/keys/{id}` (отзыв),
  `POST /api/keys/{id}/activate` (восстановление), `GET /api/keys/tenants`.
- **Ограничение частоты запросов:** внешние запросы — 70/мин обычные и
  10/мин «тяжёлые» (импорт `.xls`/`.db` и все экспорты; отдельные счётчики).
  Превышение — `429` + заголовок `Retry-After`. Локальный UI не ограничивается.
- **Аудит всех запросов к `/api/*`:** время, метод, путь, статус, IP клиента,
  длительность, результат авторизации и каким ключом (тенантом) выполнялся
  запрос; отклонённые (401/403/429) тоже логируются. Запись — через очередь в
  фоновый поток (не тормозит запросы). Чтение: `GET /api/audit`,
  `GET /api/audit/stats`; очистка: `DELETE /api/audit`. Хранение по умолчанию
  90 дней (`MEDROSTER_AUDIT_RETENTION_DAYS`).
- **CORS:** источники задаются переменной `MEDROSTER_CORS_ORIGINS`
  (по умолчанию разрешены все — безопасно, пока сервер слушает только 127.0.0.1).
- **Удалённое администрирование:** `MEDROSTER_ADMIN_TOKEN` + заголовок
  `X-Admin-Token` открывает управление ключами, аудитом, обновлением и
  остановкой сервиса с внешнего компьютера.

### Конфигурация (переменные окружения, все необязательные)
- `MEDROSTER_CORS_ORIGINS` — CORS-источники через запятую;
- `MEDROSTER_RATE_LIMIT` / `MEDROSTER_HEAVY_RATE_LIMIT` / `MEDROSTER_RATE_LIMIT_WINDOW` — лимиты (70 / 10 / 60 сек);
- `MEDROSTER_REQUIRE_API_KEY=1` — требовать ключ от всех внешних запросов даже без настроенных ключей;
- `MEDROSTER_TRUST_PROXY=1` — доверять `X-Forwarded-For` (за reverse proxy);
- `MEDROSTER_ADMIN_TOKEN` — секрет для удалённого администрирования;
- `MEDROSTER_AUDIT_ENABLED=0` — отключить аудит; `MEDROSTER_AUDIT_RETENTION_DAYS` — срок хранения.

### Техническое
- Новые модули: `app/core/config.py` (конфигурация), `app/core/api_auth.py`
  (ключи и тенанты), `app/core/rate_limiter.py` (лимиты), `app/core/audit.py`
  (аудит). Таблицы `tenants`, `api_keys`, `api_audit_log` в `med-roster.db`
  (создаются автоматически).
- 42 новых теста (`test_api_auth.py`, `test_rate_limit.py`, `test_audit_log.py`,
  обновлён `test_shutdown.py`); всего 133, все зелёные.
- `API_INTEGRATION.md` переписан под контракт `/api/v1`.

## [0.9.0] - 2026-11-16

### Новое — режим приставки
- **Режим приставки (tv-mode):** крупный интерфейс для Android-приставок и
  телевизоров. Включается двумя способами: автоматически на тач-устройствах
  (`pointer: coarse`, `ontouchstart`, `maxTouchPoints`) и вручную кнопкой
  «Режим приставки» в шапке. Выбор запоминается в `localStorage`.
- Увеличены шрифты, кнопки, поля ввода и ячейки таблицы для чтения с телевизора
  (расстояние 2–3 м); крупный редактор ячейки ещё больше (560×, шрифт 32px).

### Улучшено — доступность и UX
- Видимый фокус клавиатуры (`:focus-visible`) для навигации без мыши.
- Увеличены цели касания (`@media (pointer: coarse)`, минимальная высота 44px).
- ARIA-разметка вкладок (role=tablist/tab/tabpanel, aria-selected/controls)
  с синхронизацией состояния в JavaScript.
- Состояния `:hover`/`:active`/`:disabled` для кнопок; адаптивный редактор ячейки
  не вылезает за границы на узких экранах.

### Техническое
- Регрессионные тесты доступности и режима приставки (`test_ui.py`).
- HTTP e2e-приёмка: расписание → массовое добавление → правка ячейки → все 5
  экспортов (CSV/Т-13/ОКУД/подпись/XLS) → черновик.

## [0.8.0] - 2026-11-16

### Исправлено
- **Первый сотрудник (index=0) теперь корректно обрабатывается** инструментами
  «Заполнить» и «Скопировать график»: убраны ложные проверки `!rowIndex`, из-за
  которых первого сотрудника в списке нельзя было ни заполнить, ни скопировать.
- **Тестовый набор переведён на pytest:** старые «скриптовые» тесты с вызовом
  `sys.exit()` на уровне модуля ломали сбор тестов (`INTERNALERROR`, «no tests ran»).
  Все тесты переписаны в стиле `def test_*()`, pytest собирает и запускает их
  корректно.

### Новое — надёжность данных
- **Автосохранение черновика:** каждый шаг редактирования графика (правка ячейки,
  добавление/удаление сотрудников, автозаполнение, копирование, автокоррекция)
  автоматически пишет текущее состояние в локальный черновик. После перезапуска
  программы несохранённая работа восстанавливается (`GET /api/draft`,
  `POST /api/draft/restore`, `DELETE /api/draft`).
- **Атомарная запись черновика:** запись во временный файл с `fsync` + `os.replace`,
  чтобы при сбое на диске не оставался «половинчатый» JSON — либо старый черновик,
  либо новый, но никогда не битый. Повреждённый черновик игнорируется при запуске.
- **Предупреждение о несохранённых изменениях** при закрытии вкладки (`beforeunload`).
- **Ограничение размера загружаемых файлов** (20 МБ): защита от случайной загрузки
  гигантского `.xls`/`.db` и исчерпания памяти на слабом железе (HTTP 413).

### Улучшено — производительность
- **Кэш DOM-ячеек таблицы:** навигация и выделение ячеек больше не делают
  `querySelectorAll` по всем ~3800 ячейкам на каждое нажатие — быстрый доступ
  через карту `rowIndex:day → ячейка`. Заметно быстрее на графиках 124×31 и слабом железе.
- Добавлены регрессионные тесты: index=0, отсутствие `!rowIndex` в фронтенде,
  кэш ячеек, черновик (сохранение/восстановление/очистка), лимит размера загрузки.
- Тесты используют фикстуру `monkeypatch` для изоляции окружения вместо глобального
  `os.environ`, что делает набор воспроизводимым и безопасным при параллельном запуске.

## [0.6.2] - 2026-11-16

### Новое
- **Windows 7 SP1: DLL load failed while importing _socket (ERROR_INVALID_PARAMETER).**
  Причина - отсутствие KB2533623: вызов LoadLibraryEx с флагами
  LOAD_LIBRARY_SEARCH_* требует этого обновления, без него Python не может
  загрузить системные DLL.
- KB2533623 (x86 и x64, официальные MSU, подпись Microsoft, зафиксирован SHA256)
  включены внутри portable ZIP и установщика - скачивание с серверов MS не требуется.
- run.py проверяет наличие KB при старте (SetDefaultDllDirectories);
  при отсутствии предлагает установить через wusa.exe с проверкой SHA256.
  После установки - перезапуск приложения. Больше не нужен ручной поиск KB.
- Центр обновлений показывает статус KB на Windows 7.
- CI проверяет наличие обоих MSU в release ZIP; test_win7_prereq.py проверяет SHA256.

### Улучшено
- app/core/win7_prereq.py - проверка и установка KB2533623.
- packaging/windows/Windows6.1-KB2533623-{x86,x64}.msu - официальные MSU.
- Тест test_win7_prereq.py (SHA256, проверка spec/workflow).
