# med-roster — API для интеграции со сторонними программами

> - **Версия:** 0.11.0+
> - **Базовый URL:** `http://127.0.0.1:25625` (локально)
> - **Контракт для МИС:** те же эндпоинты с префиксом `/api/v1`; OpenAPI-схема — `GET /api/openapi.json`, Swagger UI — `GET /api/docs`
> - **Формат:** JSON (запросы/ответы), файловые форматы для экспорта

---

## 1. Общие принципы

| Аспект | Детали |
|--------|--------|
| **Авторизация** | Локальные запросы (UI с того же компьютера) — без ключа. Внешние — заголовок `X-API-Key` (см. раздел 1a). Пока ключи не выпущены — сервер работает в открытом режиме (обратная совместимость). |
| **Сессии** | In-memory (`_sessions` dict, TTL 30 мин, макс. 8 одновременных). `session_id` возвращается при создании/импорте. |
| **Лимиты запросов** | Внешние: 70/мин обычные, 10/мин «тяжёлые» (импорт/экспорт); превышение — `429` + `Retry-After`. Локальный UI — без лимитов. |
| **Аудит** | Все запросы к `/api/*` логируются: кто (ключ/тенант), что, когда, результат. См. раздел 1a. |
| **Идентификаторы строк** | `row.index` — порядковый номер (0-based) из исходного файла/создания. Не меняется при редактировании. |
| **Дни месяца** | 1-based (1…31). В JSON ключи дней — строки `"1"`, `"2"`… |
| **Коды ошибок** | `400` — плохой запрос, `404` — сессия/запись не найдена, `422` — ошибка валидации, `500` — внутренняя. |

## 1a. Интеграционный слой: ключи, лимиты, аудит (0.10.0+)

### Как это работает

| Запрос | Ключ `X-API-Key` | Поведение |
|--------|------------------|-----------|
| Локальный (127.0.0.1) | любой/нет | Работает без ключа и лимитов — как раньше (UI). |
| Внешний, ключей в системе нет | нет | Работает (открытый режим, обратная совместимость). |
| Внешний, ключи выпущены | валидный | Работает; лимиты 70/мин (тяжёлые 10/мин); аудит с тенантом. |
| Внешний, ключи выпущены | нет/неверный/отозванный | `401`. |
| Внешний, `REQUIRE_API_KEY=1` | нет | `401` всегда (даже если ключей нет). |
| Внешний с `X-Admin-Token` | — | Права администратора: ключи, аудит, обновление, остановка. |

**Тенант** — клиника/МИС, для которой выпущен ключ. Один ключ = один тенант,
полные права на данные API (роли — в следующих версиях).

### Выпуск и управление ключами (только локально или `X-Admin-Token`)

| Метод | Путь | Тело | Описание |
|-------|------|------|----------|
| `POST` | `/api/keys` | `{tenant, label?}` | Выпустить ключ. Полный ключ возвращается **один раз**. |
| `GET` | `/api/keys` | — | Список ключей (только префиксы, без секретов) + статистика. |
| `DELETE` | `/api/keys/{id}` | — | Отозвать (обратимо). |
| `POST` | `/api/keys/{id}/activate` | — | Восстановить отозванный. |
| `GET` | `/api/keys/tenants` | — | Список тенантов с числом активных ключей. |

**Ответ `POST /api/keys`:**
```json
{ "id": 1, "tenant": "МИС Поликлиника", "label": "интеграция", "key": "mrk_...", "prefix": "mrk_ab12cd34" }
```
Формат ключа: `mrk_` + 40 hex-символов. В БД хранится только SHA-256 хэш;
потерянный ключ восстанавливанию не подлежит — только перевыпуск.

### Лимиты запросов

| Класс | Лимит | Что входит |
|-------|-------|------------|
| Обычные | 70/мин | Всё, кроме перечисленного ниже. |
| «Тяжёлые» | 10/мин | `POST /api/import`, `POST /api/saved/import`, все `GET /api/export/*`. |

- Счётчики раздельные: импорт не съедает лимит обычных запросов.
- Субъект — API-ключ (авторизованные) или IP (остальные внешние).
- Превышение: `429` + заголовок `Retry-After` (секунды до сброса окна).
- Локальный UI лимитами не ограничивается.

### Аудит

Логируются **все** запросы к `/api/*`, включая отклонённые (401/403/429):
время, метод, путь, статус, IP, длительность, результат авторизации
(`authorized` / `authorized_admin` / `anonymous_local` / `anonymous` /
`rejected_bad_key` / `rejected_no_key` / `forbidden_remote` / `rate_limited`)
и каким ключом (тенантом) выполнялся запрос.

| Метод | Путь | Параметры | Описание |
|-------|------|-----------|----------|
| `GET` | `/api/audit` | `limit?`, `auth_status?`, `key_id?` | Последние записи (новые сверху). |
| `GET` | `/api/audit/stats` | — | Счётчики по статусам, топ тенантов, период. |
| `DELETE` | `/api/audit` | `older_than_days?` | Очистка (весь журнал или старше N дней). |

Запись идёт через очередь в фоновый поток — аудит не тормозит запросы.
Хранение по умолчанию 90 дней.

### Переменные окружения (все необязательные)

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `MEDROSTER_CORS_ORIGINS` | `*` (все) | CORS-источники через запятую. |
| `MEDROSTER_RATE_LIMIT` | `70` | Обычный лимит (запросов в окно). |
| `MEDROSTER_HEAVY_RATE_LIMIT` | `10` | Лимит тяжёлых (импорт/экспорт). |
| `MEDROSTER_RATE_LIMIT_WINDOW` | `60` | Окно в секундах. |
| `MEDROSTER_REQUIRE_API_KEY` | `0` | `1` — требовать ключ от всех внешних запросов. |
| `MEDROSTER_TRUST_PROXY` | `0` | `1` — доверять `X-Forwarded-For` (за reverse proxy). |
| `MEDROSTER_ADMIN_TOKEN` | пусто | Секрет для удалённого администрирования (`X-Admin-Token`). |
| `MEDROSTER_AUDIT_ENABLED` | `1` | `0` — отключить аудит. |
| `MEDROSTER_AUDIT_RETENTION_DAYS` | `90` | Срок хранения записей аудита. |

### Пример: внешний вызов с ключом

```python
import requests

BASE = "http://127.0.0.1:25625"
HEADERS = {"X-API-Key": "mrk_..."}

r = requests.get(f"{BASE}/api/v1/health", headers=HEADERS)
r.raise_for_status()

# импорт .xls (тяжёлый эндпоинт: до 10/мин)
with open("график.xls", "rb") as f:
    r = requests.post(f"{BASE}/api/v1/import", headers=HEADERS,
                      files={"file": f}, data={"year": 2026, "month": 11})
```

## 2. Справочные эндпоинты (без сессии)

### `GET /api/health`
Проверка живости сервиса.

**Ответ:**
```json
{ "status": "ok", "app": "med-roster", "version": "0.6.4" }
```

### `GET /api/calendar/{year}`
Производственный календарь РФ на год + нормы часов по неделям.

**Параметры:** `year` (int, 1990–2040+)

**Ответ:**
```json
{
  "year": 2026,
  "need_verify": false,
  "months": [
    { "month": 1, "work": 15, "short": 0, "norm": { "30": 119, "33": 131, "36": 143, "39": 155, "40": 159 } },
    ...
  ],
  "year_norm": { "30": 1428, "33": 1562, "36": 1701, "39": 1836, "40": 1881 },
  "short_days": [{ "month": 4, "day": 30 }, { "month": 5, "day": 8 }, ...],
  "holidays": [{ "month": 1, "day": 1 }, { "month": 1, "day": 2 }, ...]
}
```
- `need_verify=true` для лет вне 2020–2027 (постановлений ещё нет / авто-правило).
- `norm` — месячные нормы часов для каждой недельной нормы (30/33/36/39/40 ч).

## 4. CRUD сотрудников в сессии

Все эндпоинты требуют `sid` (session_id).

| Метод | Путь | Тело | Описание |
|-------|------|------|----------|
| `POST` | `/api/session/{sid}/employees` | `{name, position?, rate?, week_norm?}` | Добавить одного |
| `POST` | `/api/session/{sid}/employees/bulk` | `{employees: [{name, position?, rate?}, …]}` | Массово (исп. `embed=True`) |
| `PATCH` | `/api/session/{sid}/employees/{index}` | `{name?, position?, rate?, week_norm?}` | Изменить |
| `DELETE` | `/api/session/{sid}/employees/{index}` | — | Удалить |

**Примечания:**
- `week_norm` — 30/33/36/39/40. Если не задан, определяется по `position` через `classify()`.
- `rate` — 0.25…2.0 (шаг 0.25).
- При смене `position` без явного `week_norm` — переклассификация автоматически.

## 5. Редактирование ячеек и автозаполнение

| Метод | Путь | Тело | Описание |
|-------|------|------|----------|
| `POST` | `/api/session/{sid}/cell` | `{row_index, day, value}` | Записать значение в ячейку (время/код/пусто). Пересчёт валидации. |
| `POST` | `/api/session/{sid}/autofill` | `{row_index, shift, mode?}` | Заполнить пустые ячейки сменой. `mode`: `"workdays"` (только раб. дни) / `"empty"` (все пустые). |
| `POST` | `/api/session/{sid}/autocorrect` | — | Автокоррекция: норма 588н, сумма, дубликаты, сокращение предпраздничной смены. Возвращает `fixes[]`. |
| `POST` | `/api/session/{sid}/copy` | `{from_index, to_index}` | Скопировать график (врач ↔ медсестра). |

**Формат `value` для ячейки:**
- Время: `"8-15,48"`, `"12,12-20"`, `"8-12 12.30-16.30"` (разрывная)
- Коды: `"В"` (выходной), `"О"`/`"ОТ"` (отпуск), `"Б"` (больничный), `"У"`/`"ПК"` (учёба), `"Я"` (явка)
- Пусто: `""` или не передавать

## 7. Экспорт отчётных форм

Все возвращают файл для скачивания (`Content-Disposition: attachment`).

| Метод | Путь | Параметры | Формат | Описание |
|-------|------|-----------|--------|----------|
| `GET` | `/api/export/csv/{sid}` | — | CSV (UTF-8) | Исправленный график для Excel/1С. |
| `GET` | `/api/export/xls/{sid}` | `org?`, `dept?` | `.xls` (xlwt) | Нативный Excel 97-2003, колонки итогов по длине месяца. Корректно импортируется обратно. |
| `GET` | `/api/export/t13/{sid}` | `org?`, `dept?` | HTML | Табель Т-13 (печатная форма). |
| `GET` | `/api/export/okud/{sid}` | `org?`, `dept?` | HTML | Табель ОКУД 0504421 (печатная форма). |
| `GET` | `/api/export/signoff/{sid}` | `org?`, `dept?` | HTML | График на подпись (Главный врач <учреждение>). |
| `GET` | `/api/export/fhir/{sid}` | `tz?` | FHIR R4 JSON | HL7 FHIR Bundle: Practitioner/Schedule/Slot (см. 7c). |
| `GET` | `/api/export/signed/{sid}` | `org?`, `dept?`, `signer?` | ZIP | Подписанный пакет: все формы + `manifest.json` + `manifest.sig` (см. 7c). |
| `POST` | `/api/export/verify` | файл ZIP | JSON | Проверка подписанного пакета (контрольные суммы и подписи). |

- `org` по умолчанию — `DEFAULT_ORG` (`"ГУЗ СГП № 16"`), переопределяется в UI и хранится в `localStorage`.
- `dept` — подразделение (отделение), если задано в сессии/сохранении.

## 7a. Синхронизация: push/pull графиков и сотрудники (0.11.0+)

Эндпоинты для двусторонней синхронизации МИС ↔ МедГрафик без ручного UI.

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/api/v1/roster` | **Push:** принять график целиком от МИС, разобрать, провалидировать, вернуть сессию с конфликтами. |
| `GET` | `/api/v1/roster?year=&month=` | **Pull:** полный сохранённый месяц (сотрудники, дни, часы, конфликты). `404`, если месяц не сохранён. |
| `GET` | `/api/v1/employees` | Мастер-данные сотрудников из сохранённых месяцев (фильтры `year`, `month`, `department`). |
| `POST` | `/api/v1/employees/sync` | Upsert мастер-данных по ФИО в график периода. |

### `POST /api/v1/roster` — тело запроса

```json
{
  "year": 2026, "month": 11, "department": "УПО",
  "employees": [
    {"name": "Иванова И.И.", "position": "Вр. педиатр участковый",
     "rate": 1.0, "week_norm": 39,
     "days": {"2": "8-15,48", "3": "О", "4": "В"}}
  ],
  "save": true, "org": "ГУЗ «СГП № 16»", "title": "ноябрь"
}
```

- `days` — необязательный словарь «день → значение ячейки» (формат «СГП №16»,
  см. раздел 5); пустые дни можно не передавать.
- `week_norm` необязательна: без неё норма определяется по должности
  (классификатор). Допустимо 30/33/36/39/40.
- `save: true` — сразу сохранить месяц в БД (вернётся `saved_id`, вебхукам
  придёт `month.saved`).
- Ответ — стандартная структура сессии (раздел 10) + `session_id`.

### `POST /api/v1/employees/sync` — тело запроса

```json
{
  "year": 2026, "month": 11, "department": "УПО",
  "session_id": "abc...",          // опционально: синхронизировать в сессию
  "remove_missing": false,         // true: удалить сотрудников, которых нет в списке
  "employees": [
    {"name": "Иванова И.И.", "position": "Врач-педиатр"},
    {"name": "Сидорова С.С.", "position": "Медицинская сестра", "week_norm": 39}
  ]
}
```

- Без `session_id` берётся последнее сохранение за период (или создаётся
  пустой график) и открывается новая сессия.
- Сопоставление по ФИО (точное). Дни/часы существующих сотрудников
  не затрагиваются — синхронизируются только мастер-данные.
- Ответ: структура сессии + `"sync"`: `{"added": [...], "updated": [...],
  "unchanged": [...], "removed": [...], "not_in_list": [...]}` —
  `not_in_list` есть в графике, но не пришло от МИС (кандидаты на удаление;
  удаляются только при `remove_missing=true`).

## 7b. Вебхуки — уведомления МИС об изменениях (0.11.0+)

МИС регистрирует свой URL и получает POST-уведомления при изменениях.

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/api/v1/webhooks` | Список вебхуков (ключ видит только свой тенант). |
| `POST` | `/api/v1/webhooks` | Зарегистрировать: `{"url", "events"?, "tenant"?}`. Секрет доставки возвращается один раз. |
| `DELETE` | `/api/v1/webhooks/{id}` | Удалить. |
| `POST` | `/api/v1/webhooks/{id}/activate` | Включить/отключить: `{"active": true/false}`. |
| `POST` | `/api/v1/webhooks/{id}/test` | Тестовая доставка `webhook.test` (независимо от подписки). |

События: `month.saved`, `month.updated`, `month.deleted`, `schedule.changed`
(правка ячейки, автозаполнение, копирование, генерация, CRUD сотрудников,
синхронизация). По умолчанию подписка — на все, кроме `webhook.test`.

Формат сообщения:

```json
{"event": "month.saved", "ts": 1764000000.0,
 "data": {"saved_id": 3, "year": 2026, "month": 11, "department": "УПО", ...}}
```

Заголовки: `X-MedRoster-Event` (событие), `X-MedRoster-Delivery` (id доставки,
для идемпотентности), `X-MedRoster-Signature: sha256=<hex>` — HMAC-SHA256 тела
с секретом вебхука (секрет выдаётся при регистрации один раз, как API-ключ).

Нюансы доставки:

- асинхронная (фоновый поток), не блокирует запросы; таймаут —
  `MEDROSTER_WEBHOOK_TIMEOUT` (5 с), одна повторная попытка;
- быстрые повторные события по одному объекту склеиваются: пока доставка
  ждёт в очереди, новое событие того же типа по тому же объекту заменяет
  старое (при редактировании ячеек МИС увидит только самое свежее состояние);
- после `MEDROSTER_WEBHOOK_MAX_FAILURES` (10) неудач подряд вебхук
  автоматически отключается (`is_active=0`).

## 7c. HL7 FHIR R4 и подписанный пакет экспорта (0.11.0+)

### `GET /api/v1/export/fhir/{sid}?tz=+03:00`

График месяца как FHIR R4 Bundle (`type=collection`):

- **Practitioner** — сотрудник (`identifier` = ФИО, `name.text`);
- **Schedule** — расписание сотрудника на месяц (`actor` → Practitioner,
  `comment` = должность);
- **Slot** — интервал работы (`status=busy`, `start`/`end` — смена, разрывная
  смена даёт несколько слотов) или неявка (`status=busy-unavailable`:
  отпуск/больничный/учёба, `comment` = русская подпись). Выходной (В) и
  явка (Я) слотами не отражаются;
- **OperationOutcome** — warning с числом неразобранных ячеек.

`tz` — смещение часового пояса для времён (по умолчанию `+03:00`; Саратов —
`+04:00`). В query-строке «плюс» кодируйте как `%2B04%3A00` (или передавайте
`04:00` — нормализуется автоматически). Допустимы часы 00–14.

### `GET /api/v1/export/signed/{sid}?signer=...`

ZIP-пакет со всеми формами экспорта + `manifest.json` (SHA-256 и HMAC-SHA256
каждого файла, подписавший, время, версия) + `manifest.sig` (подпись
манифеста). Проверка целостности пакета (в т.ч. сторонними скриптами):

```bash
python - <<'PY'
import hmac, hashlib, json, zipfile
zf = zipfile.ZipFile("med-roster_2026-11_signed.zip")
manifest = zf.read("manifest.json")
sig = zf.read("manifest.sig").decode()
secret = open("secret.txt").read().strip()   # MEDROSTER_SIGN_SECRET
assert hmac.compare_digest(
    hmac.new(secret.encode(), manifest, hashlib.sha256).hexdigest(), sig)
for f in json.loads(manifest)["files"]:
    assert hashlib.sha256(zf.read(f["name"])).hexdigest() == f["sha256"]
print("пакет цел")
PY
```

Онлайн-проверка: `POST /api/v1/export/verify` (multipart, файл ZIP) —
`{"ok": true/false, "errors": [...], "files": [...], "signer", "generated_at"}`.

Секрет подписи: env `MEDROSTER_SIGN_SECRET` (один на все машины клиники) или
автогенерация с сохранением в БД (`settings`). **Важно:** это подпись
целостности (детект изменений и подделки), а не юридически значимая ЭЦП —
для последней нужен сертификат УЦ и ГОСТ-криптография.

## 11. Примеры интеграции

### Python: загрузка .xls, автокоррекция, экспорт CSV
```python
import requests

BASE = "http://127.0.0.1:25625"

# 1. Загрузить файл
with open("ноябрь 2026 общий.xls", "rb") as f:
    r = requests.post(f"{BASE}/api/import", files={"file": f}, data={"year": 2026, "month": 11})
session = r.json()
sid = session["session_id"]

# 2. Автокоррекция
r = requests.post(f"{BASE}/api/session/{sid}/autocorrect")
fixes = r.json()["fixes"]
print("Исправлено:", fixes)

# 3. Экспорт CSV
r = requests.get(f"{BASE}/api/export/csv/{sid}")
with open("graph_2026-11.csv", "wb") as f:
    f.write(r.content)

# 4. (опц.) Сохранить месяц в БД
requests.post(f"{BASE}/api/session/{sid}/save", json={"org": "ГУЗ СГП № 16", "dept": "УПО"})
```

### Python: чтение сохранённого месяца без UI
```python
import sqlite3, json
from pathlib import Path

# Путь к БД (Windows)
db_path = Path.home() / "AppData" / "Roaming" / "med-roster" / "med-roster.db"
# Linux: ~/.local/share/med-roster/med-roster.db

conn = sqlite3.connect(db_path)
conn.row_factory = sqlite3.Row
rows = conn.execute("SELECT id, year, month, org, dept, data FROM saved_months ORDER BY year DESC, month DESC").fetchall()

for r in rows:
    data = json.loads(r["data"])
    print(f"{r['year']}-{r['month']:02d} {r['org']} {r['dept']}: {len(data['employees'])} чел.")
    # data['employees'] — список с полями name, position, rate, week_norm, days{...}
```

## 12. Ограничения и нюансы для интеграторов

1. **In-memory сессии** — при перезапуске сервера все `sid` теряются. Для долгого хранения используйте `/api/session/{sid}/save` → `/api/saved/{id}/load`.
2. **Макс. 8 сессий** — при превышении удаляется самая старая. Не держите долго открытые сессии в скриптах.
3. **Порт 25625** — жёстко задан. Если занят, сервис не запустится (см. `run.py` + `stop.bat`/`stop.sh`).
4. **Кодировка** — везде UTF-8. В `.xls` (xlrd/xlwt) кодировка cp1251 внутри, конвертация автоматическая.
5. **Windows 7** — целевая платформа. API работает на Python 3.8+; если вызываете из современного Python — совместимости нет проблем.
6. **Авторизация** — локальный UI работает без ключа; для внешних клиентов выпустите API-ключ (`POST /api/keys`, раздел 1a). Для публикации в сеть всё равно рекомендуется reverse proxy (TLS/терминация); при нём включите `MEDROSTER_TRUST_PROXY=1`.
7. **Вебхуки** — доставка асинхронная, «at-least-once» с одной повторной
  попыткой; получатель должен быть идемпотентен (используйте заголовок
  `X-MedRoster-Delivery`). Быстрые серии событий по одному объекту
  склеиваются в одну доставку с самым свежим состоянием.

## 14. Чего НЕТ в API (пока)

- GraphQL — только REST + JSON.
- Ролей внутри тенанта (read-only / import-only) — один ключ = полные права; планируем.
- Юридически значимой ЭЦП (ГОСТ, сертификаты УЦ) — есть подпись целостности
  HMAC-SHA256 (раздел 7c); легальная ЭЦП требует внешнего криптопровайдера.
- Server-Sent Events / long-polling — изменения доставляют вебхуки (раздел 7b).
- Прямой доступ к БД извне — используйте `/api/saved/export` (скачать `.db`) или читайте файл напрямую (путь в `/api/saved` → `data_dir`).
